# DerevenkaBot · #деревенька

Telegram-бот для общения, генерации и редактирования изображений на C# / .NET 11. Telegram обслуживает библиотека **Telegram.Bot 22.10.4**. История диалогов, очереди, разрешения и учёт расходов сохраняются в SQLite, изображения — в локальном persistent storage.

В исходном репозитории была только консольная заготовка `Hello, World!`. Хост сохранён в исходном проекте; модуль можно подключить к другому боту через DI и обработчик обновлений. По умолчанию модуль и polling выключены, провайдер — fake. Реальные API-вызовы и развёртывание при разработке не выполнялись.

## Структура

```text
DerevenkaBot/                        # хост, сборка DI, конфигурация
src/DerevenkaBot.Core/
  Domain/                            # сущности и контракты данных без Telegram SDK
  Application/                       # сессии, доступ, квоты, очередь, worker, русские тексты
  Infrastructure/                    # SQLite, миграции, файлы, OpenAI и fake provider
  Telegram/                          # адаптер Telegram.Bot, команды, callbacks, polling
tests/DerevenkaBot.Tests/            # интеграционные тесты SQLite + подставные API
docs/                                # архитектура, приёмка и исходное ТЗ
```

## Проверка без ключей и сети API

Из корня решения:

```powershell
dotnet restore
dotnet build -c Release
dotnet test -c Release
dotnet run --project DerevenkaBot
```

Последняя команда выводит сообщение об отключённом модуле и завершает процесс. Тесты запускают весь путь от команды до сохранённого файла и публикации через fake Telegram; платные запросы исключены. Fake-провайдер создаёт зелёную тестовую картинку, а не интерпретирует промпт.

## Владелец и разрешения

Один раз укажите **свой числовой Telegram UserId**, не username:

```powershell
dotnet user-secrets set "ImageGeneration:OwnerUserId" "123456789" --project DerevenkaBot
```

`/ai_id` показывает ID отправителя и текущего чата даже до выдачи доступа. Эта команда не даёт разрешений. Владелец получает доступ автоматически; остальные — только по разрешению пользователя либо группы. Администратор Telegram-группы не получает право выдавать разрешения бота.

| Действие | Команда владельца |
| --- | --- |
| Разрешить всю текущую группу | `/ai_allow here` в этой группе |
| Отозвать разрешение текущей группы | `/ai_revoke here` |
| Разрешить конкретного человека | `/ai_allow 123456789` или `/ai_allow user 123456789` в личке или группе |
| Разрешить автора сообщения | Ответить на его сообщение командой `/ai_allow` |
| Разрешить группу по ID | `/ai_allow chat -1001234567890` в личке |
| Отозвать личное разрешение | `/ai_revoke 123456789`, `/ai_revoke user 123456789` или `/ai_revoke` в ответ на сообщение |
| Отозвать разрешение группы по ID | `/ai_revoke chat -1001234567890` в личке |
| Посмотреть выданные разрешения | `/ai_access` в личке |
| Рассмотреть заявки пользователей | `/ai_requests` в личке или «Заявки на доступ» в панели разрешений |

Разрешение действует до отзыва и переживает перезапуск. Групповое разрешение действует на всех участников этой группы, включая новых, и не открывает им личку. Личное разрешение действует для этого человека в личке и группах. Это независимые разрешения: отзыв одного не отменяет другого. Чтобы полностью закрыть доступ, отзовите все подходящие разрешения.

Для добавления друга по Reply ответьте на его обычное сообщение в группе командой `/ai_allow`. По `@username` доступ не выдаётся: используйте Reply или числовой UserId, который друг узнает через `/ai_id`. При Reply на пересланное сообщение используется исходный автор, если Telegram раскрывает его ID; скрытый автор не подменяется переславшим сообщение. Если бот показывает подсказку синтаксиса, права владельца распознаны, но формат аргументов не подошёл.

`AllowedUsers` и `AllowedChats` позволяют задать начальные разрешения конфигурацией. Командный отзыв имеет приоритет над соответствующей записью конфигурации. При отзыве отменяются ещё не начатые заявки, резерв возвращается. Уже начавшийся внешний запрос может быть оплачен; готовый результат не публикуется, если к моменту захвата задачи публикации доступ отозван.

### Заявки на доступ

Пользователь без разрешения открывает бота в личке и нажимает **«📨 Запросить доступ»** либо отправляет `/request_access`. В группе кнопка предлагает перейти в личку. Запрашивается личный доступ человека; разрешение всей группе по-прежнему выдаётся владельцем отдельно через `/ai_allow here`.

Владелец получает в личку карточку с именем, username (если есть), числовым ID и кнопками **«✅ Разрешить» / «❌ Отклонить»**. После решения пользователь получает уведомление. В меню владельца есть `/ai_requests`, в панели доступа — «📥 Заявки на доступ». Это позволяет рассмотреть сохранённые заявки, даже если уведомление ещё не доставилось.

Владелец должен хотя бы раз открыть личный чат с ботом и отправить `/start`, чтобы Telegram разрешил отправлять ему уведомления. При временной ошибке доставки worker повторяет только уведомление; заявка и решение остаются в БД. На пользователя допускается одна активная заявка; повторное нажатие не создаёт копии. После отклонения можно отправить новую заявку.

Принять/отклонить может только текущий `OwnerUserId` в своей личке. Решение и выдача персонального разрешения сохраняются атомарно; старые кнопки не меняют уже рассмотренную заявку и не восстанавливают отозванный доступ. Отклонение не отзывает другие независимо выданные разрешения. Ручной `/ai_allow user ID` также одобряет ожидающую заявку и запускает уведомление пользователя.

## Настройка запуска

В Git хранится `DerevenkaBot/appsettings.json` с пустыми ключами и выключенным запуском. Для локальной настройки скопируйте шаблон и заполните токен Telegram, свой числовой ID и, при работе с настоящей моделью, ключ OpenAI:

```powershell
Copy-Item DerevenkaBot/appsettings.Local.example.json DerevenkaBot/appsettings.Local.json
```

`appsettings.Local.json` исключён из Git, копируется при локальной сборке и не включается в `dotnet publish` или Docker. Файл из рабочей директории тоже поддерживается. При переименовании проекта существующие user-secrets сохраняются благодаря прежнему идентификатору хранилища. Также поддерживаются user-secrets и env; они имеют приоритет над JSON. Пример настройки через user-secrets:

```powershell
dotnet user-secrets set "Telegram:Token" "<TOKEN>" --project DerevenkaBot
dotnet user-secrets set "ImageGeneration:Enabled" "true" --project DerevenkaBot
dotnet user-secrets set "Telegram:EnablePolling" "true" --project DerevenkaBot
```

После этих настроек запуск будет подключаться к Telegram и отвечать на сообщения. Включайте его только когда готовы использовать бота. Сначала оставьте `UseFakeProvider=true`, проверьте доступ и команды на тестовом чате.

Для настоящей генерации дополнительно:

```powershell
dotnet user-secrets set "ImageGeneration:ApiKey" "<OPENAI_KEY>" --project DerevenkaBot
dotnet user-secrets set "ImageGeneration:UseFakeProvider" "false" --project DerevenkaBot
```

Также поддерживаются `OPENAI_API_KEY`, `TELEGRAM_BOT_TOKEN` и вложенные env-параметры, например `ImageGeneration__OwnerUserId`. Приоритет: базовый JSON → `appsettings.Local.json` рядом с приложением → `appsettings.Local.json` из рабочей директории → user-secrets → env → аргументы CLI. `OPENAI_API_KEY` и `TELEGRAM_BOT_TOKEN`, если заданы, перекрывают одноимённые вложенные настройки ключа/токена.

`SafetySalt` настраивать не требуется: при первом запуске реального провайдера бот генерирует случайную строку и сохраняет её в `StoragePath/safety-salt`. Она используется для обезличивания Telegram UserId и сохраняется между перезапусками вместе с данными. При желании можно задать собственный `ImageGeneration:SafetySalt` длиной от 16 символов — он имеет приоритет над файлом. Короткое заданное значение нужно удалить либо заменить; пустое или состоящее из пробелов включает автоматическую генерацию.

Пустой OpenAI key в реальном режиме или `Enabled=false` отключает модуль. Пустые allowlists и отсутствие владельца оставляют доступ закрытым. Валидность токена и доступность модели для вашей организации нужно проверить при самостоятельном подключении.

## Общение с ботом

В главном меню (`/start` или `/help`) есть выбор: **«💬 Чат»** и **«🎨 Картинки»**. «Чат» предлагает написать вопрос через «Ответить» на сообщение. «Картинки» открывает создание и изменение фото; кнопка «Главное меню» возвращает к выбору. Переход между разделами закрывает текущую подсказку, сохраняя историю и уже принятые запросы.

Отправьте `/chat вопрос`, чтобы начать разговор. Команда `/chat` без вопроса пришлёт приглашение: ответьте на него через Telegram «Ответить». Дальше продолжайте через Reply на ответы бота. Обычные сообщения без команды и Reply не запускают диалог ни в личке, ни в группе. Для изображений и управления доступом сохраняется ввод после явно выбранной подсказки в личке.

Контекст разговора отделён от картинок, разделён по пользователю и чату и хранится в SQLite после перезапуска. По умолчанию сохраняются последние 12 пар вопрос–ответ; продолжать через Reply можно с ответов из этого контекста. `/reset` очищает разговор и закрывает текущую сессию изображений. Другой участник не получает чужую историю через Reply.

Раздел `Chat` в `DerevenkaBot/appsettings.json`: `Enabled=true`, `Model=gpt-6.1-terra`, `HistoryTurns=12`, `MaxInputCharacters=8000`, `MaxOutputTokens=4096`, `TimeoutSeconds=90`, `MaxConcurrentRequests=4` (от 1 до 32). Используется тот же OpenAI key и переключатель `ImageGeneration.UseFakeProvider`. При fake-провайдере ответы явно помечаются как тестовые. Разрешения владельца/пользователя/группы действуют и для общения. `/usage` учитывает изображения; стоимость текстовых ответов туда пока не включается. Поиск в интернете не подключён.

Текст поступает через [потоковый Responses API OpenAI](https://developers.openai.com/api/docs/guides/streaming-responses). В личке при `Telegram.UseAiDrafts=true` сначала показывается Thinking, затем генерируемый текст обновляется в одном [AI Draft](https://core.telegram.org/bots/api#sendrichmessagedraft) примерно раз в секунду. Очень длинное превью показывает конец ответа; полный результат отправляется несколькими постоянными сообщениями. В группах, при выключенных drafts или неподдерживаемом endpoint используется `typing` и готовый ответ. Ошибки Telegram-индикатора не прерывают модель; 429 учитывает `retry_after`. Готовый ответ сохраняется до отправки: повтор доставки не обращается к модели заново. Обрыв потока или таймаут не вызывает автоматического платного повтора.

Обработчик сохраняет запрос в SQLite и сразу возвращается к приёму сообщений. `ChatJobWorker` обрабатывает до `Chat.MaxConcurrentRequests` разных диалогов параллельно, отдельно от очереди изображений. Диалог определяется парой пользователь/чат: один человек в разных чатах тоже может получать ответы одновременно. Вопросы внутри одного диалога выполняются по очереди с учётом предыдущего ответа. Повтор отправки сохранённого ответа сохраняет этот порядок и не задерживает другие диалоги. `/usage`, `/reset` и остальные команды принимаются во время генерации.

Очередь переживает перезапуск. Worker использует lease с продлением; оборванный запрос, который мог уже обратиться к модели, автоматически не повторяется — вместо этого отправляется уведомление о прерывании. Сохранённый ответ доставляется без повторного вызова модели. `/reset` отменяет ожидающие запросы старого контекста и не позволяет им или устаревшему ответу попасть в новый диалог. Новые настройки и миграция применяются после пересборки и перезапуска.

## Команды изображений

В личке во время генерации включён нативный AI-индикатор Thinking через live drafts Telegram. Настройка `Telegram.UseAiDrafts` по умолчанию `true`. В группах и при неподдерживаемом draft endpoint используется обычный индикатор отправки фото. Подробнее — [в описании UX](docs/ux.md).

При запуске включённого модуля бот автоматически регистрирует команды через `Telegram.Bot` (`setMyCommands`) и включает кнопку «Меню» в личке. В меню видны `/chat`, `/imagine`, `/edit`, `/reset`, `/usage`, `/help` и `/ai_id` с русскими описаниями. Команды `/ai_allow`, `/ai_revoke`, `/ai_access` добавляются только в личное меню владельца из `OwnerUserId`; в группе их можно вводить вручную. Видимость меню не заменяет проверку разрешений.

Обновление меню выполняется и без встроенного polling (например, при подключении через webhook). Существующие команды других модулей сохраняются. Для отключения авторегистрации задайте `Telegram:RegisterCommands=false`. Если Telegram временно недоступен, регистрация повторяется через 30 секунд отдельно от обработки сообщений. Если владелец ещё не открывал личку бота, сначала отправьте ему сообщение; личное меню зарегистрируется при следующей попытке. В Telegram список может обновиться после повторного открытия чата.

- `/imagine описание` — новое изображение и новая активная сессия.
- `/edit инструкция` — редактировать текущий результат или фото из Reply.
- `/reset` — очистить контекст разговора и закрыть свою сессию изображения в этом чате; история изображений сохраняется.
- `/cancel` — отменить ожидающий ввод описания/ID и черновик; активная картинка и уже принятые задачи сохраняются.
- `/usage` — дневные заявки, локальная оценка и резервы.
- `/help` — главное меню с выбором чата и картинок, владельцу также показываются команды доступа.
- `/start` — открыть главное меню.

Личные настройки и ключи меняйте в `DerevenkaBot/appsettings.Local.json`, общие параметры — в `DerevenkaBot/appsettings.json`. Копии в `bin/Debug` или `bin/Release` редактировать не нужно: при сборке настройки копируются из проекта. Для получения команд в этом самостоятельном хосте должны быть включены `ImageGeneration.Enabled=true` и `Telegram.EnablePolling=true`. Регистрация меню работает отдельно и сама по себе не включает получение сообщений. При старте режим polling явно выводится в консоль.

Поддерживаются варианты `/imagine@BotName`, `/chat@BotName` и пространство имён `/ai_imagine`, `/ai_edit`, `/ai_chat` и т. д. Обычная переписка вне выбранной подсказки игнорируется. Для изменения последней картинки используйте `/edit инструкция`, кнопку «Продолжить» или Reply на изображение. Фото/PNG/JPEG/WebP документ без текста сохраняется как черновик на `DraftMinutes` (15 по умолчанию); в группе продолжите через `/edit инструкция`.

В личке после кнопки или команды изображений/доступа без аргументов достаточно обычного следующего сообщения: Reply выбирать не обязательно. Для `/chat` и кнопки «Чат» всегда нужен Reply или явная команда. Успешный ответ завершает шаг; новая подсказка заменяет старую. Добавить/отозвать друга можно пересылкой его сообщения во время соответствующего шага; если Telegram скрыл автора, понадобится числовой ID. Неверный ID не запускает генерацию. `/cancel` и кнопка «Отмена» закрывают текущий шаг. В группе требуется явный Reply/команда; обычная переписка не перехватывается даже при открытой подсказке. Инструкция в Reply на обычную фотографию тоже принимается как редактирование, если Telegram доставил это обновление боту.

Reply на старый результат создаёт новую сессию-ветку именно от этого узла. Чужой результат можно продолжить только в той группе, где бот его опубликовал; скрытые промпты и другие файлы автора не передаются. Кнопка «Новая сессия» сбрасывает контекст нажавшего, с проверкой пользователя, чата и сообщения.

При включённом privacy mode Telegram присылает не все фото и сообщения группы: наиболее надёжный сценарий — команды и Reply на сообщение бота. Polling нельзя включать одновременно с webhook или другим polling-процессом этого же токена.

## БД, миграции и файлы

```powershell
dotnet run --project DerevenkaBot -- --migrate
```

Миграции также применяются автоматически перед запуском worker. Команда миграции не подключается к API, работает и при выключенном модуле. Создаются только таблицы с префиксом `Image`, чужие таблицы не изменяются. Версии: 1 — данные генераций, 2 — сохраняемые разрешения, 3 — ответы на интерактивные подсказки, 4 — заявки на доступ и состояние доставки уведомлений, 5 — контекст текстового диалога и состояние доставки ответов (`ImageChats`), 6 — очередь текстовых запросов (`ImageChatRequests`). Повторное применение безопасно.

По умолчанию всё хранится в `./data/image-generation` относительно рабочей директории: `images.db`, WAL/SHM и `assets/<uuid>.png`. Сохраняйте БД и assets вместе; для резервной копии остановите процесс либо используйте SQLite backup API. Не копируйте только `images.db` во время записи WAL.

Файлы проверяются по фактическому формату, числу кадров, байтам и пикселям, поворот EXIF применяется, метаданные удаляются, результат нормализуется в PNG. Произвольные URL из промпта не скачиваются. После `RetentionDays` asset перестаёт быть доступен для продолжения. Физическая очистка диска и удаление истории — P1; пока файлы удаляет владелец при остановленном боте с учётом ссылок из веток.

## Лимиты и стоимость

Лимиты количества генераций, дневного/месячного бюджета и длины очереди **отключены**: `ImageGeneration.LimitsEnabled=false` (также значение по умолчанию). Можно отправлять новые генерации без суточных/месячных квот; `/usage` продолжает показывать статистику и оценку расходов. При необходимости включить прежние ограничения можно через `LimitsEnabled=true`; числовые настройки квот и бюджета применяются только в этом режиме.

Технические параметры обработки остаются в `ImageGeneration` (см. `appsettings.json` и `ImageOptions.cs`): 2 параллельные задачи на бот, 1 на человека и на сессию. Они задают порядок выполнения без отказа новым генерациям из-за длины очереди. Продолжение ещё не готового результата требует дождаться его завершения. Счётчики UTC; часовой пояс задаётся `CounterTimeZone`. Файлы до 15 MiB и 40 млн пикселей. Для декодирования больших файлов нужен запас RAM; уменьшайте `MaxPixels` для небольшого сервера. Проверка разрешений владельца/пользователя/группы сохраняется.

При создании job сохраняется примерная стоимость `$0.25` для учёта расходов. При `LimitsEnabled=false` эта оценка не блокирует новые запросы. Если включить ограничения, применятся заданные квоты и бюджеты: дневной бюджет человека `$1.25`, бота `$7.50`, месячный `$75` по умолчанию. Это **локальные ограничения по оценке**, а не гарантия предельного списания OpenAI. Выберите консервативный резерв для разрешённой модели/параметров; отдельно настройте ограничения API-аккаунта.

`InputTextUsdPerMillion`, `InputImageUsdPerMillion`, `OutputImageUsdPerMillion` и `PricingVersion` задают версионируемые ставки. Если все ставки и детализация usage доступны, стоимость пересчитывается по токенам; иначе остаётся резервная оценка. Даже расчёт по токенам не заменяет реальный биллинг. При неопределённом результате запроса резерв сохраняется. Fake-вызовы имеют нулевую стоимость, но учитываются в количестве заявок.

Повторяются подтверждённые отказы 429 с backoff/jitter. Для 5xx, обрывов соединения и протухшего lease выполнявшейся генерации используется `Unknown` без автоматического платного повтора: провайдер мог уже выполнить работу. Ошибки параметров, авторизации и модерации не повторяются. Telegram-публикация повторяется отдельно с уже сохранённым asset. Подробные ограничения — [в архитектуре](docs/architecture.md).

## Контейнер

Скопируйте `.env.example` в `.env`, заполните токен и ID владельца. Для запуска включите `IMAGE_GENERATION_ENABLED` и `TELEGRAM_ENABLE_POLLING`. Для настоящих моделей также укажите ключ OpenAI и `USE_FAKE_PROVIDER=false`. `.env` не попадает в Git или образ контейнера.

```powershell
Copy-Item .env.example .env
docker compose build
docker compose up -d
```

Compose использует persistent volume `image-data:/data`, процесс работает от непривилегированного пользователя. Настройки берутся из env / локального `.env` (он исключён из Git): `OWNER_USER_ID`, `TELEGRAM_BOT_TOKEN`, `OPENAI_API_KEY`, `SAFETY_SALT`, `IMAGE_GENERATION_ENABLED`, `TELEGRAM_ENABLE_POLLING`, `USE_FAKE_PROVIDER`. По умолчанию контейнер безопасно завершится с выключенным модулем. `docker compose down -v` удалит данные — не используйте его для обычного обновления.
