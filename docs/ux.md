# Меню, сообщения и сценарии

Справка, статистика и разрешения используют настоящие **Rich Messages** (`sendRichMessage`, `InputRichMessage.Html`): заголовки, абзацы, списки, таблицы и раскрывающиеся пояснения. Обычные ответы, статусы и подписи к картинкам используют Telegram HTML formatting: жирный текст, курсив, код и ссылки. Динамические строки экранируются перед вставкой в HTML; toast уведомления callback отправляются обычным текстом без тегов.

## Что видит пользователь

- `/start` и `/help` открывают главное меню с двумя основными кнопками: «💬 Чат» и «🎨 Картинки». Короткая инструкция находится в раскрывающемся блоке «Как пользоваться».
- «💬 Чат» просит написать вопрос через «Ответить». Нажатие кнопки не вызывает модель. Обычный текст без ответа на сообщение не запускает диалог.
- «🎨 Картинки» открывает кнопки «✨ Создать картинку» и «✏️ Изменить фото». Кнопка «🏠 Главное меню» возвращает к выбору режима. Переход в меню закрывает незавершённую подсказку, сохраняя историю и принятые запросы.
- «✨ Создать картинку» просит описание через ForceReply. Ответ на подсказку создаёт новую сессию; нажатие кнопки само по себе ничего не генерирует.
- `/chat вопрос` начинает текстовый разговор. `/chat` без текста просит вопрос через Reply; дальнейшие вопросы тоже отправляются ответом на сообщения бота. Обычный текст вне выбранного шага игнорируется и в личке, и в группе.
- Несколько диалогов отвечают параллельно (по умолчанию до 4), в том числе у одного пользователя в разных чатах. Вопросы одного пользователя в одном чате идут по очереди с общим контекстом. Генерация ответа не блокирует новые команды; `/reset` отменяет ожидающие запросы старого контекста.
- В личке после выбора действия с картинкой или доступом достаточно следующего обычного сообщения. Одновременно открыт один шаг, он сохраняется после перезапуска и завершается после успешного действия. Для `/chat` всегда нужен Reply или команда. Чужие и просроченные подсказки не принимаются.
- Ввод можно отменить через `/cancel`, а в личке — кнопкой под подсказкой. Это отмена ввода и черновика, а не отмена принятых задач или сброс текущей картинки. Старая кнопка отмены не закрывает более новый шаг.
- Команды из меню без аргументов (`/imagine`, `/edit`, `/ai_allow`, `/ai_revoke`) тоже открывают подсказку: следующий ответ используется как описание или ID, а не запускает случайную генерацию.
- «✏️ Изменить» просит инструкцию для текущей картинки. Под результатом «✏️ Продолжить» привязывает ответ именно к выбранному результату, даже если после него появились другие картинки.
- Если исходника нет, «Изменить» сначала предлагает прислать фото. Инструкцию можно добавить к фото сразу или следующим сообщением.
- «📎 Оригинал» отправляет сохранённый PNG документом без Telegram-сжатия и без вызова OpenAI. Этот документ тоже можно продолжить через Reply.
- «🆕 Новая сессия» сбрасывает контекст нажавшего. История остаётся доступной.
- `/usage` открывает таблицу: заявки сегодня, задачи в работе и локальная оценка расходов. Отключённые квоты показаны как отключённые.
- `/ai_id` показывает User ID и Chat ID моноширинным текстом с кнопками копирования в буфер.
- «🗂 История и данные» объясняет хранение и приватность с учётом текущего `RetentionDays`.

Кнопки основных действий синие, выдачи доступа — зелёные, отзыва — красные. Используются стандартные emoji; дополнительные платные emoji не требуются.

## Доступ для друзей

Пользователь без доступа видит приветствие и кнопку «📨 Запросить доступ». В личке заявка сохраняется одним нажатием (также доступна `/request_access`); из группы кнопка ведёт в личный чат с ботом. Владелец получает карточку с двумя решениями — «Разрешить» и «Отклонить». Пользователь получает результат решённой заявки и, при одобрении, главное меню. Повторное нажатие на отправку не создаёт ещё одну ожидающую заявку.

«📥 Заявки на доступ» в панели владельца и `/ai_requests` показывают ещё не рассмотренные заявки с теми же кнопками решений. Список доступен только в личке владельца. Если владелец ещё не начинал личный диалог с ботом, ему нужно отправить `/start`; доставка сохранённого уведомления повторится автоматически.

Владелец в личке видит «🔑 Управление доступом»: таблицу действующих/отозванных разрешений, включая начальные allowlists. «🤝 Добавить друга» и «🔐 Отозвать» предлагают ответить числовым ID через ForceReply. Ручные `/ai_allow ID`, `/ai_allow here` и Reply-команды продолжают работать.

На шаге выдачи/отзыва доступа можно просто переслать сообщение человека. Определяется видимый исходный автор; при скрытом авторе бот просит ID и не выдаёт доступ переславшему сообщение. Неверный ID оставляет шаг открытым, а не превращается в промпт изображения. Одиночное число вне выбранного шага игнорируется; для намеренной генерации по числу есть явный `/imagine`.

В группе административная панель не раскрывает список разрешений. Пользовательская навигация всегда проверяет того, кто нажал кнопку; административные действия повторно проверяют владельца. Разрешение группы и человека остаются независимыми.

## Статус без лишних сообщений

До начала обработки запрос получает сообщение `⏳ Запрос принят`. Когда в личке успешно показан нативный Thinking через `sendRichMessageDraft`, обычное сообщение очереди удаляется: остаётся один индикатор прогресса и затем результат-картинка. При неподдерживаемом draft endpoint либо в группе сохраняется одна обычная карточка: `⏳ Запрос принят` → `🎨 Рисую…` → `📤 Отправляю…` → `✅ Картинка готова`. Она редактируется, а не отправляется заново. Ошибки редактирования/удаления статуса не запускают повторную генерацию и не теряют успешный результат.

`ImageStatusService` согласует переходы между этими режимами и поздний ответ на отправку сообщения очереди. После пропадания native draft один обычный статус может быть восстановлен, без создания копии на каждом тике. Повтор одного текста не вызывает дополнительного edit. Терминальная ошибка после native draft сохраняется отдельным постоянным сообщением. Доступ к UI-состоянию задачи сериализован внутри процесса, чтобы handler и worker не создавали две карточки одновременно.

## AI live drafts

Используются официальные [AI features for bots](https://core.telegram.org/api/bots/ai) и [sendRichMessageDraft](https://core.telegram.org/bots/api#sendrichmessagedraft). `Telegram.UseAiDrafts=true` включает их (значение по умолчанию); `false` возвращает `upload_photo` и в личке. Draft обновляется каждые 4 секунды с постоянным ненулевым ID для job. Он показывает честный статус создания изображения, а не имитацию потока токенов: текущий Images API возвращает готовый бинарный результат.

Draft доступен в личке и является временным превью, обычно до 30 секунд без обновления. Он исчезает при получении нового обычного сообщения (в нашем успешном сценарии — результата-картинки) либо по TTL. На терминальной ошибке отправляется постоянное сообщение ошибки, которое также завершает временный draft. Результат сохраняется обычным сообщением с картинкой; в режиме без drafts сохраняется обычная карточка статуса.

Для `/chat` Responses API используется с `stream=true`. До первого текстового фрагмента показывается Thinking, затем один и тот же draft обновляется накопленным текстом примерно раз в секунду; при паузе превью обновляется каждые 4 секунды. Длинное превью показывает последние 3500 символов. После завершения полный ответ сохраняется через `sendRichMessage` (при необходимости несколькими сообщениями), чтобы на него можно было ответить. История и ID опубликованных ответов сохраняются в `ImageChats`, отдельно по пользователю и чату. `/reset` очищает контекст разговора. HTML из текста модели экранируется.

При 400/404 от endpoint используется fallback `upload_photo` для изображений и `typing` для диалога до перезапуска процесса. В группах и при `UseAiDrafts=false` текстовый ответ отправляется после завершения с индикатором `typing`. При 429 учитывается `retry_after`; модель продолжает работу без повторного вызова. Ошибка UI не теряет готовый ответ. Обрыв OpenAI-потока не считается успешным завершением и не запускает автоматический платный повтор. Нативная кнопка Stop не включена.

Если задача начала работать до сохранения ID сообщения очереди, позднее сообщение удаляется при активном draft либо используется как единственная обычная карточка. Если ошибка успела прийти раньше подтверждения очереди, запоздалое сообщение очереди удаляется, а ошибка сохраняется.

Подсказки сформулированы коротко: «Напиши вопрос», «Опиши картинку», «Что изменить?». В группе ссылка-упоминание находится в инструкции «Нажми „Ответить“ на это сообщение и напиши текст», чтобы ForceReply с selective reply адресовался инициатору. `ImagePromptReplies` сохраняет автора, чат, действие, сообщение-источник и TTL (`DraftMinutes`). Чужой ответ или просроченная подсказка не запускают генерацию. Reset закрывает ожидающие подсказки. Повтор callback не выполняет действие второй раз.

В личке используется совмещённая inline-клавиатура с `force_reply=true` и кнопкой отмены. В группе сохраняется selective ForceReply, чтобы не открывать ввод всем участникам. Там обычный текст без Reply не захватывает даже открытая подсказка.

Навигация и обновление статистики в личке редактируют одну карточку. Ответ «message is not modified» при повторном обновлении считается успешным. Если исходное сообщение больше нельзя редактировать, открывается новая карточка. В группе карточки не перезаписываются другим участником.

Фото без подписи сохраняется черновиком и сопровождается одной адресованной подсказкой: достаточно ответить инструкцией, в том числе в группе.

## Проверенные возможности API

На 17.11.2026 изучены изменения вплоть до Bot API 10.4 от 09.11.2026. Применены поддерживаемые установленным Telegram.Bot 22.10.4 возможности:

- [Rich Message Formatting](https://core.telegram.org/bots/api#rich-message-formatting-options) — полноценные структурированные сообщения.
- [HTML formatting](https://core.telegram.org/bots/api#html-style) — короткие ответы и подписи.
- [InlineKeyboardButton](https://core.telegram.org/bots/api#inlinekeyboardbutton) — стили primary/success/danger и copy_text.
- [ForceReply](https://core.telegram.org/bots/api#forcereply) — адресованный ввод без запоминания команд.
- [EditMessageText](https://core.telegram.org/bots/api#editmessagetext) и [SendChatAction](https://core.telegram.org/bots/api#sendchataction) — аккуратные статусы.

Все сетевые проверки разработки используют fake HTTP, бот с реальными ключами не запускался. Отображение Rich Messages и цветных кнопок нужно проверить в актуальном Telegram-клиенте после пересборки и перезапуска бота.
